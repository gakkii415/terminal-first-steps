# 実装計画

## ステータス

要件とMVP仕様は確定済みです。次の作業は`index.html`の作成です。この文書の段階ではコードを追加しません。

## 1. 最小ディレクトリ構成

```text
terminal-first-steps/
├── index.html                 # 次フェーズで作成するアプリ本体
├── README.md
└── docs/
    ├── requirements.md
    ├── mvp-spec.md
    └── implementation-plan.md
```

- MVPでは`package.json`、CSSファイル、JavaScriptファイル、画像を作らない
- HTML、CSS、JavaScriptは`index.html`へまとめる
- ビルドやインストールなしで確認できる構成にする

## 2. JavaScriptの責務

単一ファイル内でも、役割を次の順に分けます。

1. 定数: 初期ファイル構成、レッスン、文言
2. 状態: 現在地、仮想ファイル、進捗、履歴
3. 仮想ファイル操作: 検索、移動、作成、一覧、読み取り
4. コマンド処理: 入力解析、7コマンドの実行、エラー生成
5. レッスン判定: 各ステップの成功条件確認
6. 永続化: 保存、復元、破損データの初期化
7. 表示: レッスン、履歴、進捗、完了状態の描画
8. イベント: Enter送信、ヒント、リセット、再フォーカス

想定する主要な責務名は、`parseCommand`、`executeCommand`、`resolvePath`、`evaluateStep`、`saveState`、`loadState`、`render`です。実装時に不要な抽象化やクラスは追加しません。

## 3. 実装順序

### Step 1: 静的な画面骨格

- ヘッダー、レッスン欄、ターミナル欄、フィードバック欄を置く
- モバイル幅でも入力欄が見える最小CSSを入れる
- セマンティックな要素とラベルを先に用意する

### Step 2: 初期データと状態

- 初期仮想ファイルシステムを定義する
- 全8ステップの目的、説明、ヒント、成功条件を定義する
- 初期状態を1か所から生成できるようにする

### Step 3: コマンド実行

- 入力を正規化してコマンドと引数に分ける
- `pwd`、`ls`、`cd`、`mkdir`、`touch`、`cat`、`clear`の順に追加する
- 各コマンドへ正常系と初心者向けエラーを用意する

### Step 4: レッスン進行

- 実行後の状態で成功条件を評価する
- 成功フィードバックと次ステップを表示する
- Step 8完了後に完了画面へ切り替える

### Step 5: 保存とリセット

- 操作後に`localStorage`へ保存する
- 初期表示時に安全に復元する
- 確認付きリセットを実装する

### Step 6: 最小検証

- 8ステップを最初から最後まで通す
- 不正入力、再読み込み、リセットを確認する
- PC幅とスマートフォン幅で主要操作を確認する

## 4. 手動テスト項目

| No. | 操作 | 期待結果 |
|---:|---|---|
| 1 | 初回表示 | Step 1と空の入力欄が表示され、入力欄にフォーカスする |
| 2 | `pwd` | `/home/learner`を表示してStep 2へ進む |
| 3 | 全8ステップを実行 | 完了画面が表示される |
| 4 | `abc` | 未対応コマンドの日本語案内を表示し、状態を維持する |
| 5 | `cd missing` | 存在しないフォルダの案内を表示する |
| 6 | `mkdir practice`を2回実行 | 2回目は同名エラーになり、既存データを壊さない |
| 7 | 空入力でEnter | 履歴や進捗を変更しない |
| 8 | `clear` | 表示履歴だけを消し、進捗と仮想ファイルは残す |
| 9 | 途中で再読み込み | 進捗、現在地、作成物を復元する |
| 10 | リセットを承認 | Step 1と初期ファイル構成へ戻る |
| 11 | リセットをキャンセル | 状態を変更しない |
| 12 | 375px幅で操作 | 横スクロールなしで入力と進行ができる |

## 5. Definition of Done

MVP実装は、次をすべて満たした時点で完了とします。

- `index.html`だけでアプリが起動する
- 8ステップの正常系を完走できる
- 7コマンドと主要エラーが仕様どおり動く
- 進捗保存、復元、リセットが動く
- 実OS、ネットワーク、外部APIへアクセスしない
- ブラウザのコンソールに未処理エラーが出ない
- PC幅と375px幅で手動テストを通す
- READMEに実行方法が記載される
- MVP完成後に停止し、UI改善へ勝手に進まない

## 6. 実装時に変更しない判断

- 疑似ターミナル方式
- フロントエンドのみ
- 外部依存なし
- 単一`index.html`
- 日本語UI
- 1コース、8ステップ、7コマンド
- バックエンド、認証、DB、本番公開は対象外

## 7. 後続フェーズへ延期するもの

- 見た目の本格的なブランド設計
- 高度なアニメーションやマイクロインタラクション
- 複数レッスンと自由練習
- 実ターミナル連携
- ユーザーアカウントとクラウド同期
- GitHub Pagesなどへの公開

## 8. 次の一手

`main`ブランチに`index.html`を新規作成し、上記のStep 1からStep 6までを順番に実装します。MVPが動作した時点で停止し、レビューを依頼します。
